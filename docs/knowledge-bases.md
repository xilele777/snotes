# 个人笔记本

笔记本功能从 v0.19.0 起提供，v0.20.0 统一笔记与笔记本的导航和交互。应用版本以 package.json 为准；部署及发布结果见[更新记录](roadmap.md#更新记录)。

## 使用

以下说明对应当前工作区交互；未发布的调整见 CHANGELOG 的 Unreleased 条目。

1. 点击统一侧栏的「笔记本」进入总览，点击卡片打开相应笔记本；通过总览顶部「新建」创建笔记本。总览可按名称/简介搜索、按更新时间或名称排序；固定的笔记本优先显示。侧栏不再单独展示笔记本列表。
2. 顶部「新建笔记」「添加内容」默认将内容放入根目录。章节的「⋯」菜单提供「在此新建笔记」「在此加入笔记」「新建子章节」；加入笔记和创建章节时，可在弹窗中调整位置。单击目录只负责浏览和展开/收起，不改变顶部创建位置。目录选项可以全部展开或收起，方向键在可见条目间移动焦点。
3. 「添加内容 → 加入笔记」选择已有笔记，「新建笔记」复用现有编辑器。相同笔记可以加入多个笔记本，同一本笔记本内只引用一次。原分组与首页可见性保持原设置。总览使用卡片网格；首页显示名称、实际简介、笔记与章节数量、创建与更新时间，笔记统一从目录打开。
4. 桌面可拖动：拖到章节中放入该章节，拖到笔记前放在其前面，拖到目录底部移至根目录末尾。章节同级排序和手机操作使用目录菜单的「上移」「下移」「移动到…」。
5. 笔记本内搜索匹配目录标题及笔记标题、已下载正文；多个关键词按空格分隔取交集。离线无法搜索未下载正文。
6. 从目录移除引用或章节不会删除笔记。笔记本顶栏或卡片的「⋯」菜单提供编辑、固定、目录快照与删除。删除需联网并输入完整笔记本名称确认，会永久删除笔记本及其中的笔记、图片和历史记录，不进入回收站，无法撤销；同一笔记在其他笔记本中的内容也会删除，并显示已删除占位。确认前先完成同步；其他设备更新了目录时需重新确认。界面不再提供「已移除的笔记本」或恢复入口。

桌面侧栏可通过顶部按钮收起为图标栏或展开，手机保留完整抽屉。分组分区可以折叠；侧栏、分组折叠状态、固定的笔记本与排序仅保存在本设备。隐藏笔记从侧栏「已隐藏笔记」直接访问。回收站、统计和设置在底部同步状态上方纵向排列。

桌面显示目录与首页/正文；720px 及以下显示可展开的笔记本信息和目录，打开笔记后进入正文，返回恢复目录位置。笔记本视图切换沿用浏览器导航历史。

## 同步与快照

所有笔记本使用现有实例 ACCESS_TOKEN。没有成员、邀请、角色、笔记本级权限或多人编辑功能。

笔记与笔记本共用左下角云朵同步入口，失败状态也统一呈现；目录冲突仍在相应笔记本内处理。本机数据先写 IndexedDB，再上传服务端。元数据和目录使用不同版本；创建笔记本、创建被引用笔记后，才上传目录。网络恢复与手动同步清除网络退避，冲突仍需手动解决。连续调整目录合并为最新结构；发出后的请求持久保存，响应丢失时按原 operation_id 重试，后续编辑不被旧确认删除。

服务端通过版本条件写入拒绝过期修改。客户端分别保留本机与远端目录，在「查看并选择」中选定版本；只暂停发生冲突的任务。另一台设备永久删除笔记本后，删除状态优先于本机未同步的目录修改，本机副本和待上传任务随同步清理，不会通过冲突选择恢复。旧版可恢复移除数据保留兼容，不会静默删除其中的笔记。

「目录快照」浏览本机保留的确认、冲突和选择前快照，可重新应用目录。重新应用不恢复或删除笔记正文；笔记本不可用或仍有同步冲突时不能重新应用；永久删除会同时清理该笔记本的快照。确认快照保留最近 50 份，冲突快照不会随普通清理删除。服务端也在每次目录变更时原子保存旧结构，保留最近 50 份；当前界面浏览本机快照。

## 备份兼容

设置 → 数据 → 导出全部，默认生成格式 2：包含笔记、分组、图片、笔记本元数据、目录与本机保留快照；同一篇笔记正文只导出一次。被目录或快照引用的回收站笔记也保留回收站状态，不在导入时恢复为正常笔记。

应用继续兼容导入格式 1。导出固定使用完整格式 2，不再提供省略笔记本的旧版导出选项。完整备份应在支持笔记本的版本中导入。

导入按原笔记与笔记本 ID 对齐。重复导入不复制正文或目录；遇到同 ID 的笔记本内容不同，保留现有笔记本并保存导入快照，提示冲突数量。从「保留的快照」可查看替代内容。缺失正文保留引用占位，不创建同 ID 的空笔记。一次导入一个带索引的备份包。

## 存储与接口

- IndexedDB 升级为 v3，追加 knowledgeBases、knowledgeBaseTocs、knowledgeBaseOutbox、knowledgeBaseTocHistory、knowledgeBaseNoteStates；保留既有表与数据。
- 迁移 `0006_knowledge_bases.sql` 提供元数据、目录聚合、目录历史、操作确认与独立单调变更时钟；v0.21.0 的 `0007_permanent_notebook_deletion.sql` 追加永久删除标记、笔记删除记录和图片清理队列，防止迟到创建或旧客户端恢复已删内容。
- 节点使用 id / parent_id / ord，只有章节可以做父节点；每个笔记本最多 1000 节点、8 层、结构 JSON 1 MiB。
- D1 batch 与 SQLite batch 在同一事务中执行条件版本写入、历史快照、笔记本变更序号与操作确认；请求幂等记录独立于有界历史。

| 接口 | 契约 |
| --- | --- |
| POST `/api/knowledge-bases` | id、operation_id、完整元数据；客户端指定身份，重复返回原确认 |
| PATCH `/api/knowledge-bases/:id` | 完整元数据、base_meta_version、operation_id；旧版 invalid 状态仅保留兼容，永久删除后返回 410 |
| POST `/api/knowledge-bases/:id/delete` | 完整 name、base_meta_version、base_toc_version；名称精确校验，原子删除内容并推进同步序号，过期返回 409，重复请求可安全重试 |
| GET `/api/knowledge-bases/:id/toc` | book、toc、note_states；永久删除时附 deleted_note_ids 供跨设备清理，不返回正文 |
| PUT `/api/knowledge-bases/:id/toc` | nodes、base_toc_version、operation_id；过期返回 409 + current |
| POST `/api/knowledge-bases/sync/pull` | since、after、until；独立序号分页，固定上界，每页最多 50 个笔记本 |

目录导入/快照可指定 preserve_missing_references=true，仅保留占位，不修改笔记实体。保存本机已确认移除笔记本的结构时需 archived_meta_version，防止远端移除被当作本机归档意图。相同 operation_id 不能重用为不同请求。

## 开发与上线

开发验证先在隔离测试数据库执行迁移。v0.19.0 上线时已在生产数据库应用 0006；v0.20.0 正式版本没有新增数据库迁移；v0.21.0 新增 0007。上线前复查迁移状态，结果记录在[更新记录](roadmap.md#更新记录)。

本地 Node.js 启动时沿用迁移扫描，自动追加未应用的迁移（包括本轮 0007）。Cloudflare 上线时，需要在目标数据库应用新迁移，再部署匹配的新服务端和前端。旧服务端会收到客户端的笔记本请求，但返回不支持；界面明确提示升级，不影响原笔记接口。

正式发布按根目录 AGENTS.md 的版本、CHANGELOG、测试、构建、提交、标签、推送、部署与 Release 流程执行。
