# 个人知识库

知识库功能从 v0.19.0 起提供，v0.20.0 统一笔记与知识库的导航和交互。应用版本以 package.json 为准；部署及发布结果见[更新记录](roadmap.md#更新记录)。

## 使用

以下说明对应 v0.20.0 的统一导航改版，变更记录见 CHANGELOG 对应版本。

1. 点击统一侧栏的「知识库」进入总览，或直接点击侧栏中的知识库名称。总览可按名称/简介搜索、按更新时间或名称排序；固定的库优先显示。侧栏「我的知识库」旁的加号也可以新建。
2. 顶部「新建笔记」「添加内容」默认将内容放入根目录。章节的「⋯」菜单提供「在此新建笔记」「在此加入笔记」「新建子章节」；加入笔记和创建章节时，可在弹窗中调整位置。单击目录只负责浏览和展开/收起，不改变顶部创建位置。目录选项可以全部展开或收起，方向键在可见条目间移动焦点。
3. 「添加内容 → 加入笔记」选择已有笔记，「新建笔记」复用现有编辑器。相同笔记可以加入多个库，同一库内只引用一次。原分组与首页可见性保持原设置。总览使用卡片网格；首页显示名称、实际简介、笔记与章节数量、创建与更新时间，笔记统一从目录打开。
4. 桌面可拖动：拖到章节中放入该章节，拖到笔记前放在其前面，拖到目录底部移至根目录末尾。章节同级排序和手机操作使用目录菜单的「上移」「下移」「移动到…」。
5. 库内搜索匹配目录标题及笔记标题、已下载正文；多个关键词按空格分隔取交集。离线无法搜索未下载正文。
6. 从目录移除引用或章节不会删除笔记。知识库顶栏或列表条目的「⋯」菜单提供编辑、固定、目录快照与移除。移除后在「知识库总览 → ⋯ → 已移除的知识库」恢复。笔记回收站状态不因目录恢复而改变，彻底删除的引用显示占位。

桌面侧栏可通过顶部按钮收起为图标栏或展开，手机保留完整抽屉。分组与知识库分区可以折叠；侧栏、分区状态、固定的知识库与排序仅保存在本设备。隐藏笔记从侧栏「已隐藏笔记」直接访问。回收站、统计和设置在底部同步状态上方纵向排列。

桌面显示目录与首页/正文；720px 及以下显示可展开的知识库信息和目录，打开笔记后进入正文，返回恢复目录位置。知识库视图切换沿用浏览器导航历史。

## 同步与快照

所有知识库使用现有实例 ACCESS_TOKEN。没有成员、邀请、角色、库级权限或多人编辑功能。

笔记与知识库共用左下角云朵同步入口，失败状态也统一呈现；目录冲突仍在相应知识库内处理。本机数据先写 IndexedDB，再上传服务端。元数据和目录使用不同版本；创建知识库、创建被引用笔记后，才上传目录。网络恢复与手动同步清除网络退避，冲突仍需手动解决。连续调整目录合并为最新结构；发出后的请求持久保存，响应丢失时按原 operation_id 重试，后续编辑不被旧确认删除。

服务端通过版本条件写入拒绝过期修改。客户端分别保留本机与远端目录，在「查看并选择」中选定版本；只暂停发生冲突的任务。另一台设备移除库时，保留本机目录会明确恢复知识库。

「目录快照」浏览本机保留的确认、冲突和选择前快照，可重新应用目录。重新应用不恢复或删除笔记正文；库已移除或仍有同步冲突时，先恢复库或解决冲突。确认快照保留最近 50 份，冲突快照不会随普通清理删除。服务端也在每次目录变更时原子保存旧结构，保留最近 50 份；当前界面浏览本机快照。

## 备份兼容

设置 → 数据 → 导出全部，默认生成格式 2：包含笔记、分组、图片、知识库元数据、目录与本机保留快照；同一篇笔记正文只导出一次。被目录或快照引用的回收站笔记也保留回收站状态，不在导入时恢复为正常笔记。

应用继续兼容导入格式 1。导出固定使用完整格式 2，不再提供省略知识库的旧版导出选项。完整备份应在支持知识库的版本中导入。

导入按原笔记与知识库 ID 对齐。重复导入不复制正文或目录；遇到同 ID 的知识库内容不同，保留现有库并保存导入快照，提示冲突数量。从「保留的快照」可查看替代内容。缺失正文保留引用占位，不创建同 ID 的空笔记。一次导入一个带索引的备份包。

## 存储与接口

- IndexedDB 升级为 v3，追加 knowledgeBases、knowledgeBaseTocs、knowledgeBaseOutbox、knowledgeBaseTocHistory、knowledgeBaseNoteStates；保留既有表与数据。
- 服务端追加迁移 `migrations/0006_knowledge_bases.sql`，共五张表：元数据、目录聚合、目录历史、操作确认与独立单调变更时钟。
- 节点使用 id / parent_id / ord，只有章节可以做父节点；每库最多 1000 节点、8 层、结构 JSON 1 MiB。
- D1 batch 与 SQLite batch 在同一事务中执行条件版本写入、历史快照、库变更序号与操作确认；请求幂等记录独立于有界历史。

| 接口 | 契约 |
| --- | --- |
| POST `/api/knowledge-bases` | id、operation_id、完整元数据；客户端指定身份，重复返回原确认 |
| PATCH `/api/knowledge-bases/:id` | 完整元数据、base_meta_version、operation_id；invalid=1 移除，0 恢复 |
| GET `/api/knowledge-bases/:id/toc` | book、toc、note_states；不存在/已清理引用不返回正文 |
| PUT `/api/knowledge-bases/:id/toc` | nodes、base_toc_version、operation_id；过期返回 409 + current |
| POST `/api/knowledge-bases/sync/pull` | since、after、until；独立序号分页，固定上界，每页最多 50 个库 |

目录导入/快照可指定 preserve_missing_references=true，仅保留占位，不修改笔记实体。保存本机已确认移除库的结构时需 archived_meta_version，防止远端移除被当作本机归档意图。相同 operation_id 不能重用为不同请求。

## 开发与上线

开发验证先在隔离测试数据库执行迁移。v0.19.0 上线时已在生产数据库应用 0006；v0.20.0 没有新增数据库迁移。上线前复查迁移状态，结果记录在[更新记录](roadmap.md#更新记录)。

本地 Node.js 启动时沿用迁移扫描，自动追加 0006。Cloudflare 上线时，需要在目标数据库应用新迁移，再部署匹配的新服务端和前端。旧服务端会收到客户端的知识库请求，但返回不支持；界面明确提示升级，不影响原笔记接口。

正式发布按根目录 AGENTS.md 的版本、CHANGELOG、测试、构建、提交、标签、推送、部署与 Release 流程执行。用户已授权 v0.20.0 提交、部署和推送；此前留在本地的 v0.19.0 提交与标签一并推送。
