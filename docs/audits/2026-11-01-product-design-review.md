# snotes 产品设计与交互审阅

审阅日期：2026-11-01。应用版本：根目录 package.json 的 1.0.6。

后续优化见[实施与验证记录](2026-11-01-product-design-optimization.md)。本文保留修复前的发现与复现条件。

本次审阅覆盖布局、操作流程、信息组织、保存与同步反馈、删除恢复、搜索、备份和统计。检查了 Vue 组件、数据仓库、同步入口及相关测试，并在独立数据目录的本地 Node 服务（127.0.0.1:8793）中用测试数据验证。没有修改业务代码，没有访问或修改生产数据。

结论：主要问题是普通笔记与笔记本的功能规则没有统一，以及若干边界状态缺乏完整反馈。视觉风格本身相对统一，优先解决“找不到内容、操作结果不符合预期、无法完成备份”，比全面换肤更有价值。

优先级定义：P1 为优先处理的核心流程阻断；P2 为影响使用正确性或效率的问题；P3 为需要专项验证的扩展性风险。以下明确区分实测缺陷、设计取舍与静态风险。

## 1. P1：合法空正文会阻断整个备份

**类型：浏览器实测缺陷。**

复现：通过应用支持的 API 创建正文为 `''` 的笔记，同步到浏览器，在“设置 → 数据”点击“导出全部”。界面报“导出失败：部分笔记正文尚未下载，无法完成备份”。该正文实际存在且已同步，空字符串是合法内容。

原因：`fillBodies()` 用空字符串同时表示空笔记和缺失正文，随后把 `body === '' && body_version > 0` 一律当作缺失。见 [backup.ts](../../src/export/backup.ts#L173)，关键判断在第 195 行。

影响：一条合法空笔记就能让所有内容无法导出，错误提示还会把用户引向无效的重复同步。实测中，刚从 UI 新建空白笔记后立即导出未必失败；这里确认的是“已同步且实际正文为精确空字符串”的场景，不能把所有空白编辑器都视为同一种状态。

建议：通过 bodies 表是否存在对应记录来判断正文是否缺失，保留空字符串的合法含义。验收覆盖已同步空正文、尚未同步空正文、正文记录缺失，以及包含这些笔记的混合备份。

截图：`tmp/design-review-backup-error.png`。

## 2. P2：分组较多时，笔记菜单超出视口且不能内部滚动

**类型：浏览器实测布局缺陷。**

复现：准备 20 个分组，在 390 × 844 视口打开列表行的笔记操作菜单。菜单一次性列出全部分组，实测高度约 1458px，底部删除入口落到视口之外。菜单的计算样式为 `max-height: none`、`overflow-y: visible`。

原因：[NoteList.vue:317](../../src/components/NoteList.vue#L317) 将全部分组展开；[ActionMenu.vue:29](../../src/components/ActionMenu.vue#L29) 只调整位置；[styles.css:132](../../src/styles.css#L132) 未限制高度和提供内部滚动。

建议：给菜单设置基于可用视口的最大高度和内部滚动；“移至分组”采用独立选择器，可搜索，并把删除等固定动作与长列表分开。验收还应覆盖手机横屏、短窗口与触屏条件。

截图：`tmp/design-review-menu-overflow.png`。

## 3. P2：连续删除后，撤销第一条会丢掉第二条的撤销入口

**类型：浏览器实测交互缺陷。**

复现：在第一条撤销提示仍显示时，再删除第二条；点击当前“撤销”。第一条被恢复，但第二条排队中的撤销提示被清空，不会接着显示。第二条仍可从回收站恢复，因此这里不是永久丢失数据。

原因：[notify.ts:52](../../src/notify.ts#L52) 的 `runNoticeAction()` 调用 `dismissNotice()`；后者会把整条消息队列清空。前面的排队设计因此只保证等待到期时顺序播放，不能保证执行撤销后的顺序播放。

建议：把“消费当前提示”和“清空所有提示”拆开；撤销当前操作后继续显示下一条待处理提示。连续删除多条时，也可以合并成带数量的批量撤销提示。

## 4. P1：名为“全部笔记”，实际却没有全局检索入口

**类型：已实测的产品语义问题。**

“全部笔记”会排除笔记本内笔记，也排除“隐藏”笔记。普通搜索只扫描当前列表；笔记本总览搜索名称和简介；进入某一本后才搜索该本的标题与已下载正文。用户不记得归属时，需要在多个位置逐一查找。

复现：在笔记本内正文写入“海盐星球”，返回“全部笔记”搜索该词，结果为 0。页面提示换个词，没有提示笔记本内容不在当前范围。分组空态中的“在全部笔记中搜索”也不会成为真正的全局搜索。

依据：[repo.ts:388](../../src/db/repo.ts#L388)、[NoteList.vue:198](../../src/components/NoteList.vue#L198)、[KnowledgeBaseWorkspace.vue:31](../../src/components/KnowledgeBaseWorkspace.vue#L31)。

建议：让“全部笔记”包含所有未删除内容，结果中标记分组或笔记本位置；若必须保留独立信息流，则将其改称“随手记”或“首页”，另设明确的全局搜索。全局搜索应明确是否包括隐藏内容、回收站和未下载正文。

## 5. P2：笔记本内仍展示作用不明确的星标、分组和首页显示操作

**类型：已实测的上下文不一致。**

笔记本内可以星标，但侧栏“星标笔记”排除了这些笔记；可以设置分组，但分组列表同样排除笔记本笔记；菜单里还有“不在首页信息流显示”，但笔记本内容本来就不进首页。编辑器顶栏展示的是“未分组”，没有直接呈现实际所属笔记本和章节。

实测：打开已星标的笔记本笔记，按钮为 `aria-pressed=true`，侧栏星标列表却显示 0 条。

依据：[NoteDetail.vue:417](../../src/components/NoteDetail.vue#L417)、[NoteDetail.vue:481](../../src/components/NoteDetail.vue#L481)、[NoteMenu.vue:58](../../src/components/NoteMenu.vue#L58)、[repo.ts:398](../../src/db/repo.ts#L398)。

建议：统一全局星标和搜索；位置展示采用“笔记本 / 章节”。若普通笔记与笔记本坚持分离，应隐藏当前上下文不产生可见效果的控制，并提供明确的移出/移动操作。

截图：`tmp/design-review-notebook.png`。

## 6. P2：删除容器的业务规则差异过大

**类型：有意设计的风险，不是缺少确认的 bug。**

删除分组保留笔记；删除单篇笔记进入回收站；删除整本笔记本却把其中内容永久删除，绕过回收站。当前已经有完整名称确认、数量提示和不可撤销说明，这些保护应保留，但它们没有消除用户对删除规则的学习成本。

依据：[DeleteNotebookDialog.vue:20](../../src/components/DeleteNotebookDialog.vue#L20)、[GroupSidebar.vue](../../src/components/GroupSidebar.vue)、[worker/knowledge-base-deletion.ts](../../worker/knowledge-base-deletion.ts)。

建议：默认提供可恢复的“笔记本回收站”，或者让用户选择“解散笔记本并保留笔记”。永久删除应作为次级危险操作，并明确引用图片的保留策略。现有代码为旧共享引用提供了警告，后续设计也应继续考虑这些历史数据。

## 7. P2：“连续编辑天数”和热力图并不是编辑历史

**类型：静态确认的统计模型问题。**

热力图、连续天数和最长连续天数来自每条笔记当前唯一的 `update_time`，不是逐日编辑事件。例如连续三天编辑同一篇笔记，最终只剩最后一天；再次编辑还会让先前那一天的统计消失。属性调整或删除也能改变更新时间，不能等同于写作。

另外，统计页先排除笔记本内容，将笔记收入笔记本后，会改变普通统计的覆盖范围。当前页面“编辑热力图”“全年写作热力图”“连续 / 最长”的表达容易让用户理解成完整写作记录。

依据：[shared/stats.ts:159](../../shared/stats.ts#L159)、[shared/stats.ts:203](../../shared/stats.ts#L203)、[StatsView.vue:61](../../src/components/StatsView.vue#L61)、[stats-activity.ts](../../src/stats-activity.ts)。

建议：若保留写作统计，记录按日期聚合的正文编辑事件，并区分属性操作；若暂不增加记录模型，应改称“现存笔记最近更新时间分布”，移除连续写作指标，明确统计范围。

## 8. P2：离线缺正文时，页面一直显示“正在打开编辑器”

**类型：浏览器故障注入实测。**

复现：在新浏览器上下文中让元数据同步成功，阻断 `/api/sync/bodies`，打开笔记后切为离线。手机详情只有“正在打开编辑器…”，没有说明这条正文尚未下载，也没有正文下载重试入口。

原因：`currentBody === null` 同时代表正在加载、尚未缓存和下载失败。[notes.ts:102](../../src/stores/notes.ts#L102) 对缺失正文直接返回；[NoteDetail.vue:581](../../src/components/NoteDetail.vue#L581) 继续展示同一个 EditorLoading。

普通搜索也只扫本地 bodies 表，界面没有提供正文未下载数量，不能把“没有搜索结果”当作“云端不存在”。笔记本搜索已经有“已下载正文”的范围说明，可作为统一反馈的起点。

建议：区分加载中、未缓存、离线、下载失败；显示“本机尚未下载此笔记正文，联网后可读取”，提供重试和返回。搜索应提示当前索引完整度。

截图：`tmp/design-review-offline-loading.png`。

## 9. P2：保存状态和同步状态离实际编辑位置太远

**类型：界面实测与静态检查确认的反馈缺口。**

全局状态主要位于侧栏底部，默认文字是“自动同步”。手机编辑时侧栏收起，详情顶栏没有当前笔记的本地保存状态、待同步状态或最后成功同步时间。“自动同步”描述功能是否启用，不能回答“刚写的这段话有没有保存到本机、另一台设备能不能看见”。

现有本地保存失败提示、草稿恢复和数据页失败任务入口是有效保护；问题是正常状态与失败后的持续可见性不足，不应把这些已有能力误写成缺失。

依据：[GroupSidebar.vue:38](../../src/components/GroupSidebar.vue#L38)、[GroupSidebar.vue:56](../../src/components/GroupSidebar.vue#L56)、[NoteDetail.vue:257](../../src/components/NoteDetail.vue#L257)、[settings/DataPane.vue](../../src/components/settings/DataPane.vue)。

建议：在编辑区域增加轻量状态，例如“保存中 / 已保存到本机 / 等待同步 / 已同步”；错误保留可见入口，点击进入可读的恢复界面。避免让用户必须理解任务 UUID、kind 和原始任务 JSON 才能恢复内容。

## 10. P2：手机工具栏只是缩窄了桌面工具栏

**类型：实测 UI 和触控效率问题；不是整页横向溢出。**

在 390px 和 320px 视口，格式按钮实测约 23 × 36px，工具栏内容宽度约 543px。撤销、重做位于长工具栏后段，手机需横向滚动才容易到达；首屏却摆放了大量低频格式操作。顶栏继续突出置顶和星标，当前归属缩成一个文件夹图标。

依据：[vditor.css:44](../../src/editor/vditor.css#L44)、[VditorEditor.vue:622](../../src/editor/VditorEditor.vue#L622)、[styles.css:458](../../src/styles.css#L458)。

建议：手机固定显示撤销/重做、待办、图片及格式入口，其余格式放进展开面板；增大触控区域。归属信息可用简短文字或位置面板表达。桌面可以保留较完整的格式工具栏。

截图：`tmp/design-review-390.png`、`tmp/design-review-mobile-stable.png`。

## 11. P3：进入笔记本模块会订阅全部笔记本的正文

**类型：静态扩展性风险，未进行大规模性能压测。**

[knowledge-bases.ts:33](../../src/stores/knowledge-bases.ts#L33) 的订阅收集所有目录及冲突目录里的笔记 ID，再批量读取全部正文。它在 [KnowledgeBaseWorkspace.vue:309](../../src/components/KnowledgeBaseWorkspace.vue#L309) 挂载时启动，包括笔记本总览场景。相关数据变化还会使查询重新运行。

普通列表已经采用按需正文和虚拟滚动，而笔记本模块重新全量载入正文，数据多时可能使进入总览、搜索和持续编辑的内存及读库成本增长。这里没有测量实际耗时，不应直接判定当前小数据量使用已卡顿。

建议：总览只订阅元数据和预计算摘要；当前笔记本按范围加载；跨本搜索使用独立索引；字数使用可更新的聚合值。用数千篇、多笔记本、持续编辑场景验证后再确定优化规模。

## 建议处理顺序

1. 修复空正文备份、超长菜单和连续撤销；三项都有具体复现路径。
2. 确定“全部笔记 / 随手记 / 笔记本”的范围，统一搜索、星标和归属显示，再调整导航文字。
3. 补正文下载失败和保存/同步状态；调整手机工具栏。
4. 统一删除与恢复语义，纠正统计模型；单独评估大数据量性能。
