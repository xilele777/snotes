## 第一轮性能记录（本轮最终复测见下方）

浏览器任务全部退出、最终生产构建完成后，普通正文和长文各独立运行三轮。条件为 500 条合成笔记、390×844、4 倍 CPU 降速、4 Mbps/40 ms、静态资源 gzip。可复核的逐轮原始结果在 [startup-results.json](2026-10-19-startup-results.json)。

| 场景（中位数） | 修复前审查基线 | 第一轮结果 |
| --- | ---: | ---: |
| 普通正文：列表显示 | 1,383 ms | 1,621 ms |
| 普通正文：点击到编辑器可用 | 1,658 ms | 1,663 ms |
| 普通正文：缓存刷新恢复编辑器 | 646 ms | 769 ms |
| 长文：点击到编辑器可用 | 约 9,700–10,014 ms（IR 单轮诊断） | **1,583 ms**（自动源码分屏，三轮中位数） |
| 长文：缓存刷新恢复编辑器 | 约 12,039–12,300 ms（IR 单轮诊断） | **871 ms**（三轮中位数） |

长文改善来自避免首次构造整篇 IR DOM，约降低 84% 的首次等待、93% 的缓存刷新等待；它通过改变首开模式实现，不宣称 IR 解析本身变快。普通正文的点击时间基本持平，列表与 warm 本轮没有改善，因此**不能承诺所有页面都已经秒开**。宿主机状态存在波动，普通正文第一轮列表为 2,556 ms，另外两轮为 1,621/1,536 ms，已保留全部结果。下一轮应继续围绕真实手机上的启动长任务、列表恢复、Lute 首次 602 KB 传输和解析做预算。

六轮均未记录 pageerror、同步 XHR；冷启动长任务中位数普通正文 1,271 ms、长文 1,153 ms，长文仍受 Lute 解析与预览成本影响。profile 临时服务器原本就启用 gzip，Node 静态压缩的收益另由服务端回归验证；没有拿这个脚本冒充生产 CDN 测量。

## 使用边界

- 正文同步和导入上限为 **1 MiB UTF-8**。本地输入超限不会被静默截断；服务端拒绝并保留失败任务，可导出后拆分。
- 一次选择的导入文件总大小最多 100 MiB；ZIP 最多 10,000 个条目，单条解压最多 32 MiB，累计声明解压最多 256 MiB。校验在 fflate 分配各条目解压缓冲前执行。
- 长文自动分屏阈值为 50,000 个 JS 字符，属于可调整的性能策略，不是内容容量上限。主动切回 IR/WYSIWYG 仍可能卡顿，不能宣称底层 Lute/DOM 成本已消失。
- 草稿同时依赖内存和 localStorage 兜底；浏览器同时拒绝 IndexedDB 与 localStorage 时，只能保留当前页面内存并提示下载，不能保证强制结束进程后恢复。
- 当前备份包含正常笔记、分组、笔记本及其引用的回收站正文；普通笔记历史和未引用的普通回收站内容不包含，界面已明示。

## 第二轮修复的行为与边界

### 加载前闪正文与跳动

原来的纯文本预览会先显示 Markdown，然后被带工具栏和不同排版的 Vditor 替换，产生两次内容布局；初始化中的编辑器也可能和占位同时占用高度。本轮删除预览、骨架和过时样式，固定编辑区域最小高度，初始化根绝对定位并隐藏、inert，就绪后撤销隐藏。空笔记聚焦等待 Vue 移除 inert，避免新建后无法输入的回归。

三模式、Markdown 往返、旧空行、高亮、嵌套列表、链接、表格和图片的当前 Vditor 浏览器回归继续保留；旧 Milkdown 测试及专属实现删除。历史设计文档只添加当前状态提示，不改写已发布记录。清理旧依赖不等于 Lute 变小，也不能据此声称首次打开明显加快。

开发依赖扫描入口限定为正式 `index.html`，避免把 tmp 下的审查页和历史参考 HTML 当成应用入口。最后生产构建、类型检查和资源预算通过；本地迁移 0010 已应用，开发服务恢复。未触及线上数据库。

### 对账与恢复

新增迁移 `0010_sync_checkpoints.sql`，不改已应用迁移。凭证 7 天到期，短于 30 天墓碑期；缺失、过期、游标高于服务端时上传前从零对账。只在全部分页、正文完整且末尾远端水位验证成功后推进游标和处理未出现记录；中途失败保留原游标和未出现记录。存在待上传正文时不覆盖本地输入；远端版本回退时先保留历史。已确认删除的墓碑不无谓复活，待上传正文仍另存副本。

**这不是数据库快照/恢复协议的完整实现。** 同水位恢复、只回滚笔记本表无法仅靠 note watermark 自动识别，恢复操作必须先清空 `sync_checkpoint`；文档已补。笔记本远端完全缺失的清单没有独立缺失对账，永久删除的本地笔记本也不会自动复活。分页完成到后续上传之间仍有跨请求窗口，持续远端写入会令全量对账反复重试。严格闭环需要服务端实例 epoch（覆盖两个同步域）、恢复钩子和带版本的完整清单/快照，另加旧客户端兼容策略。

远端没有记录时无法判断是正常删除已过墓碑期，还是服务器恢复到了创建之前。当前保留正文为独立冲突/恢复副本，优先避免丢失，可能让旧的已删除文本重新出现在列表中，需人工合并；不能称为无感恢复。分组/笔记本的完整缺失清理同样未宣称完成。

### 图片和导入

已提交图片暂缓永久回收，移除“删除原笔记本就禁止共享图片读取”的限制，原有鉴权仍执行。该策略关闭当前后台误删离线/跨笔记引用对象的路径，代价是存储累积、删除笔记不擦除图片；持有效凭证和已知图片 URL 仍可能读取。引用表、可恢复删除队列、写入协调与离线重传协议仍待实施。

导入先校验完整索引、重复 ID/路径、日期、属性、目录和正文限制，再准备全部必需图片，失败不提交笔记。分组、正文、目录、历史和同步任务统一在 IndexedDB 事务提交；同 ID 差异正文不覆盖现有文本，去重保存在历史中。图片上传位于事务外，同一索引备份重试按内容哈希复用上传凭证。散装 Markdown 重试可能重新上传；云端上传不是原子恢复，失败可留下孤立对象。普通历史与普通回收站仍不属于完整备份范围。
