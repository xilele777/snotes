## 本次已修复：顶部高度与垂直对齐

根因是 `styles.css` 已定义 `--header-height: 64px`，但后加载的 `workspace.css` 将侧栏品牌区覆盖为 76px，抽屉断点又覆盖为 68px。桌面侧栏的中心因此比列表和编辑区低约 6px。手机编辑器、统计和列表也有各自的高度值。

- 侧栏、列表、编辑器、笔记本、设置和统计顶部统一使用 `--header-height`：桌面/平板 64px，≤720px 为 60px。
- 移除局部高度覆盖。笔记本目录标题改用 flex 垂直居中，不再依赖上下不对称的 padding。
- 侧栏和笔记本目录保留透明的底边框占位，与其他顶栏的边框盒一致，内容中心线相同。
- 控件与图标不强行使用相同的可见尺寸；品牌、标题、按钮按同一中心线对齐。控件尺寸体系作为后续规范项处理。

桌面浏览器测量：侧栏、列表、编辑器的顶部均为 y=0、高度 64px；品牌按钮、新建按钮、分组入口的垂直中心均为约 31.6px（浏览器缩放下的亚像素值）。手机列表、编辑器、抽屉品牌区和笔记本目录均为 60px。侧栏收起后仍为 64px。

## 待规范项目

以下项目未随本次高度修复实施。P2 表示影响操作或可辨识性，P3 表示视觉与维护一致性；不将建议全部当作功能缺陷。

### 1. P2：设置单选组缺少对应的键盘交互

**浏览器确认。** 设置 → 外观 → 主题，聚焦「浅色」后按 ArrowRight，焦点与选中值仍留在「浅色」。当前所有选项均为普通可 Tab 聚焦按钮，声明 `role="radio"`，但没有方向键处理或组内 tabindex 管理。

依据：`src/components/settings/AppearancePane.vue:37` 起的各个 `radiogroup`。

建议：抽取统一的分段单选控件，或使用原生 radio；每组只保留一个 Tab 入口，左右方向键切换选项，焦点与 `aria-checked` 同步。覆盖主题、列表密度、字号、编辑宽度、行距和表格密度。

验收：仅用键盘可遍历各组并更改选项，刷新后保存的选项保持正确。

### 2. P2：移动端触控区域没有统一尺寸

**浏览器测量 + 静态确认。** 390px 视口中，返回按钮为 32×40px，分组入口高度 36px，置顶/星标/更多为 40×40px；设置开关的 CSS 点击盒为 42×24px。侧栏条目和菜单条目却已按 44px 最小高度处理。

依据：`src/styles.css` 的 `.back-btn`、`.editor-location`；`src/workspace.css` 的手机 `.op-btn`；`src/pages.css:22` 的 `.settings-switch`。

建议：将触屏操作区域统一为至少 44×44px 的项目目标，图形本身可以更小；开关用较大的外部按钮承载视觉轨道。桌面保留紧凑布局。增加宽度时重新核算 320px 顶栏预算，低频操作继续放进更多菜单。

验收：320/390px 下不挤压位置文本、不横向溢出，相邻点击区域不重叠。这里是项目易用性目标，并非本次已完成的无障碍合规评估。

### 3. P2：浮层存在两套定位与键盘处理

**静态确认的实现差异，短视口裁切风险尚未专项复现。** `ActionMenu.vue` 使用 Teleport、视口边界定位、最大高度和方向键导航；编辑器的分组/颜色/笔记本浮层使用局部 absolute 定位和独立事件。分组浮层高度上限是固定 300px，不是当前可用视口高度。`NoteDetail.vue` 的 `toggle()` 会主动聚焦浮层按钮，但 `onMenuAction()` 的颜色/笔记本分支直接设置状态，入口间的焦点行为不一致。

依据：`src/components/ActionMenu.vue:29`、`src/components/NoteDetail.vue:191`、`src/components/NoteDetail.vue:243`、`src/styles.css` 的 `.op-popover` 和 `.groups-pop`。

建议：共享浮层定位、关闭和焦点归还基础设施；菜单与选择器保留各自适合的语义。统一处理 Esc、外部点击、视口翻转、内部滚动和入口焦点。

验收：从直接按钮和更多菜单打开同一选择器，焦点行为一致；手机横屏、短窗口和长分组列表中，全部操作均可到达。

### 4. P3：笔记本选中态与 hover 使用同一背景

**静态确认。** 普通侧栏和笔记选中使用 `--selected-bg` / `--accent-soft`；笔记本目录的 `.kb-tree-row.selected` 与 hover 都用 `--bg-hover`，仅通过字重补充区分，`.kb-home-link.active` 也采用 hover 色。

依据：`src/components/knowledge-base.css:42`、`:48` 起的 active/selected/hover 规则。

建议：统一「当前选中」「鼠标悬停」「按下」「禁用」的语义颜色。笔记本目录可使用已有 selected 变量，并保留字重或标记作为额外线索。

验收：浅色与深色主题下，将鼠标移到非选中项时，仍能明确识别当前项。

### 5. P3：按钮、字号、间距和圆角缺少统一档位

**静态确认 + 桌面测量。** 新建按钮 34px、图标按钮 32px、编辑器操作按钮 30px、页面返回按钮至少 36px，圆角分散为 5/6/7px；顶级标题有 17/18/19px，水平 padding 有 18/24/28px。部分差异符合场景，但没有明确规则说明何时使用哪档。

依据：`src/styles.css` 的 `.icon-button`、`.header-create`、`.op-btn`；`src/pages.css` 的 `.workspace-page-header h1`、`.page-back`；`src/components/knowledge-base.css` 的 `.kb-book-heading h2`。

建议建立小规模 token 表，逐步替换同类值：

| 项目 | 建议规则 |
| --- | --- |
| 顶部容器 | 已实施：64px / 手机 60px，唯一变量来源 |
| 桌面控件 | 紧凑 32px、常规 36px；同一操作行统一档位 |
| 触屏区域 | 44px 最小点击区域，图标视觉大小独立 |
| 字级 | 页面标题 18px，常规标签 14px，紧凑内容 13px，辅助信息 12px；正文设置独立 |
| 间距 | 优先使用 4/8/12/16/24/32px，必要例外写清用途 |
| 圆角 | 控件 6px、浮层 8px、卡片 12px；胶囊和圆形另算 |
| 颜色与状态 | 继续复用现有主题变量，补充统一的危险操作 hover 变量 |

这些是后续设计约定建议，不要求一次性替换所有数值，也不应破坏信息密度与响应式布局。

### 6. P3：样式归属与当前规范文档需要收敛

**静态确认。** `styles.css` 定义基础规则，`workspace.css` 再覆盖相同类，页面文件继续覆盖局部规则；本次 76px 覆盖就是这种组织方式造成的漂移。`docs/ui-refresh.md` 明确混合了当前说明和历史记录，历史部分仍描述旧图标栏、弹窗式统计/设置、隐藏手机状态栏等行为，不适合作为唯一当前规范。

建议：为 shell、基础控件、页面分别指定样式归属；颜色/尺寸变量集中管理，避免靠加载顺序修补同一个组件。另保留一份只描述当前行为的简短 UI 规范，历史记录继续留档。优先处理本次涉及的 header、button、popover 和 segmented control，不需要引入大型组件库。
