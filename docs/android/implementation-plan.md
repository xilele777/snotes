# Android 开发实施计划

[客户端设计](README.md) · [同步与 API 契约](sync-contract.md)

日期：2026-11-20。状态：M0–M3 核心实现与本地自动验收完成，正在推进 M4–M6；人工输入法、真机和系统选择器专项保留在安装包人工验收清单。M3 两套隔离后端与 ACK 前强杀恢复通过，结果见 [M3](acceptance/2026-11-20-m3.md)。先完成内部可用 APK，再增加系统入口、完整数据管理与发布加固。

## 1. 执行规则

每个阶段完成后记录代码位置、验证命令、设备、结果和已知限制。阶段按依赖推进，编辑器和同步的关键失败未关闭前，不用增加功能绕过验收。

| 阶段 | 交付物 | 前置条件 | 退出标准 |
| --- | --- | --- | --- |
| M0 工程与契约基线 | 可构建原生工程、冻结工具链、跨语言测试向量 | 本文与设计文档 | 空应用安装成功，基础契约对照通过 |
| M1 编辑器原型 | 离线编辑页面、消息桥、输入与保存会话 | M0 | 中文输入与最后一次 flush 可验证，编辑路线确定 |
| M2 本地笔记 | Room、Repository、离线列表 / 编辑 / 恢复 | M1 | 不联网可完成本地写作，重启可恢复 |
| M3 服务端同步 | 两域预检、pull / push、outbox、冲突与恢复 | M2 | 核心契约、故障注入、两套后端联通通过 |
| M4 首个内部可用版本 | 手机导航、普通笔记管理、只读笔记本、图片与后台 | M3 | 首版功能清单全部验收，生成内部 APK |
| M5 系统与扩展功能 | 接收分享、小组件；笔记本管理与完整备份专项 | M4 | 分项验收，不扩大原有数据风险 |
| M6 发布加固 | 性能、实机、升级、签名与发布记录 | M4；选定的 M5 项目 | 发布门禁通过，限制写入发布说明 |

没有按日估算工期。M1 的真实输入与长文结果、M3 的恢复兼容结果决定后续工作量。

## 3. M1：编辑器与输入原型

### 任务

- [x] 创建 `android/editor-web/` 最小编辑页面，固定 Vditor / Lute 资源，通过 AGP 生成 assets。
- [x] 只加载本地资源，不启动 Service Worker / IndexedDB；关闭 Vditor 独立正文缓存与 WebView DOM 存储。
- [x] 用 WebViewAssetLoader 和受 origin 限制的消息接口接入 ready / load / change / flush / saved。
- [x] 实现 sessionId、noteId、revision 与 requestId 校验，拒绝旧会话与非主 frame 的消息。
- [x] 保留原始 Markdown 基线，初始化 / 模式转换不写回；自动化验证历史空行、高亮、列表、任务、表格、代码和本地样例图片。
- [x] 实现原生串行保存会话、原子草稿日志和提交 receipt，用文件测试 Repository 验证 ACK；完整 Room 在 M2 接入。
- [x] 切笔记与系统返回前 flush 实时值；Activity 重建保留已捕获的输入，旧 ACK 不影响新文档。
- [x] 接入 IME insets、格式工具栏、textarea 选区和触摸滚动；外链由系统浏览器打开，人工输入与无障碍检查待补验。
- [x] 准备普通样例与超过 76,000 字符 / 2,000 段落长文；长文只在源码模式打开，预览按需生成。
- [ ] 人工验收常用中文输入法候选、实际选区 / 撤销、旋转、后台与长文性能。

### 决策与验收

至少使用一种常用中文输入法和系统输入法实测拼音候选、输入法组合文本、换行、删除、光标、选择、撤销、横屏和后台切换。初始化后无编辑时，不产生保存请求。

当前按用户“先用现有模拟器验证”的选择推进，采用源码 + 预览作为后续本地笔记路线；IR 保留试用状态。原生 InputConnection 与合成 DOM 输入只能验证自动化路径，不能把人工候选、TalkBack 或真机性能记为已通过。

编辑 A 后立刻切到 B，A 的最后一次 flush 仍绑定 A；B 不继承 A 的撤销栈。持久化 ACK 对应的 revision 在重启后内容一致，尚未 ACK 的输入窗口单独记录。

即时渲染不能通过时记录原因并使用源码 + 预览；若 WebView 输入方案整体不通过，按客户端设计改为原生纯文本编辑原型。进入 M2 前明确采用哪条路径及其限制。

## 4. M2：本地优先核心

### 任务

- [x] 实现独立 profile 的数据库、图片与草稿目录，首版只激活一个实例。
- [x] 创建 notes / bodies / groups / outbox / sync_meta / history / drafts 与笔记本读取表，导出 Room schema。
- [x] 实现 Repository：新建、正文保存、属性修改、普通删除 / 撤销 / 恢复、草稿另存、单篇导出。
- [x] 每次正文保存把正文、派生字段、历史与任务同事务提交；prop 修改累积字段；删除 / 恢复保留最终意图。
- [x] 实现 StateFlow 保存状态，区分保存中、本机已保存、保存失败与尚未同步。
- [x] 列表只读元数据，使用 Paging；详情按 ID 读正文，缺正文与空串明确区分。
- [x] 实现本机中文子串搜索与取消机制，显示未下载正文的覆盖边界。
- [x] 把 M1 保存会话接入 Room；事务记录已提交 revision，重启恢复文件 / drafts 时跳过旧日志，按基线检查冲突。
- [x] 配置 Android 备份排除规则，避免自动迁移令牌、密钥依赖与未同步数据库。

### 验收

飞行模式下完成新建、连续编辑、星标、分组、搜索与单篇导出；重启后持久化数据和 outbox 一致。保存中出现磁盘写入失败时不会显示“已保存”，恢复入口可找到可读草稿。

通过 Room 测试覆盖保存与入队原子性、属性累积、删除 / 恢复意图顺序、空正文、事务回滚和基线冲突。主库提交后、草稿文件清理前退出进程，重启不能重放旧稿。系统立即结束进程的结果按持久化 revision 统计，不能只测试正常退出。

本阶段收尾结果见 [M2 验收记录](acceptance/2026-11-20-m2.md)。70 项 JVM、28 项模拟器测试与新进程恢复通过；立即强杀边界及系统选择器导出仍待专项验收。

- [x] 实现正文冲突副本、create replay、404 / 410、永久失败另存与导出。
- [x] 实现全量清点、水位验证、失踪恢复和同水位 revision 变化处理；重启后不跳过恢复标记。
- [x] 实现笔记本只读同步、目录验证、引用状态与删除恢复，使用独立时钟与分页结束条件。
- [x] 使用 MockWebServer 注入超时、丢响应、401 / 409 / 410 / 429 / 413、缺正文与乱序完成。
- [x] 连接隔离的 Node.js 与 Worker 测试实例，使用 Web 同款 API 与 Android 交替编辑；人工界面互编留待验收。

### 验收

[同步契约的最低验收集](sync-contract.md#11-最低契约验收集) 全部通过；两套真实后端均完成创建、属性修改、正文冲突、删除恢复、图片鉴权与实例恢复演练。受保护操作必须带正确 epoch，不支持必需端点的服务端明确拒绝接入。

服务端接受请求但响应丢失、进程在 ACK 事务前退出、清点进行中再次恢复服务端是单独测试用例，不能由正常成功路径推导。

- [ ] 测试前台 / Worker 争用、Doze、断网、强制停止与任务重启；UI 不承诺固定后台同步时刻。
- [ ] 完成系统返回、edge-to-edge、IME、TalkBack、大字体、小屏与横屏测试。

### 首版场景清单

| 场景 | 预期 |
| --- | --- |
| 新安装接入自托管实例 | 验证令牌、读出列表；未下载正文不能误编辑 |
| 已有缓存，断网冷启动 | 列表不等网络，已下载正文可用，缓存缺图有提示 |
| 飞行模式编辑后联网 | 本机内容保留，任务自动续传，Web 端可见 |
| Web 与 Android 同时编辑 | 冲突可见，原文能找回，属性没有被正文 ACK 吞掉 |
| 连续输入后立刻切笔记 / 切后台 | flush 正确绑定会话，已确认 revision 可恢复 |
| 令牌失效 | 提示修复，已有内容可继续离线读写，任务保留 |
| 服务端从备份恢复 | 先对账，失踪记录保留正文副本，再上传 |
| 笔记本内容被其他端调整 | 目录刷新与引用状态正确，不发送未实现的结构变更 |
| 本机保存失败 / 服务端拒绝正文大小 | 原稿有可读恢复入口；状态不误称成功 |
| 联网图片上传时切换笔记 | 不把图片插入新文档，已写正文不受影响 |

M4 通过后才进入实际日常试用。内部包仍说明后台限制、离线图片范围、目录只读和备份尚未完整；不得用“与网页端完全一致”概括。

## 8. M6：性能、升级与发布

### 性能预算

以下为初始目标，尚未实测。M0 指定实际中档测试机，M6 记录 release/profileable 构建、WebView、样本、网络、温度和轮次；不以 debug 或桌面模拟器结果宣布达标。

| 指标 | 初始目标 | 测量边界 |
| --- | --- | --- |
| 本地冷启动到列表可交互 | P95 ≤ 1 秒 | 500 条元数据，有本机缓存，分别测在线 / 离线 |
| 打开普通已缓存笔记到可输入 | P95 ≤ 2 秒 | 约 2,000 字符，包含编辑器准备时间 |
| 大列表 | 5,000 / 20,000 条规模可分页滚动 | 内存、帧时间与搜索延迟单独记录 |
| 长文 | 源码模式可打开、输入和保存 | 约 76,000 字符 / 2,000 段落，记录实测耗时，不设虚假的即时渲染目标 |
| 前后台与耗电 | 无重叠同步、无后台轮询常驻 | Doze / 网络恢复 / 厂商限制，记录实际调度延迟 |

预算不达标时先排查启动是否等待网络、是否读了全部正文、是否提前初始化编辑器。任何预算变更需记录设备与原因；不能删除慢样本来得到通过结果。

### 升级与安全验收

- [ ] 增加 `:benchmark` 与基准测试，至少 10 次有效轮次报告中位数和 P95。
- [ ] 对同签名旧 APK 覆盖安装，验证 Room 升级、旧草稿、未完成 outbox、checkpoint 与图片缓存。
- [ ] 验证备份排除、令牌密钥失效、profile 更换和旧 Worker 取消。
- [ ] 确认正式包中日志、WebView 调试、明文网络与测试服务器配置已关闭。
- [ ] 复核 WebView 消息来源、外链、外部图片、重定向和路径访问边界。
- [ ] 记录设备矩阵：最低支持系统、当前主流系统、不同 WebView / 输入法、至少一台有明显省电限制的真机。
- [ ] 配置签名与 CI 密钥来源，密钥不入库；生成 APK，渠道需要时再生成 AAB。
- [ ] 在 GitHub Release 附产物、SHA-256、设备验收摘要、协议兼容范围和限制。

### 构建与验证命令

Android 工程已创建，Debug 构建、JVM / 模拟器测试、lint 与未签名 Release 构建已在 M0 执行；以下正式签名 / AAB 命令仍需相应阶段配置和验收。

Windows 从仓库根目录执行：

```powershell
# 现有 Web / Worker / Server 验证；正式发布必跑
npm run test:all
npm run build

# M0 建立的 Android 任务
.\android\gradlew.bat -p android :app:testDebugUnitTest :app:lintDebug :app:assembleDebug

# 有模拟器 / 真机时执行 instrumentation
.\android\gradlew.bat -p android :app:connectedDebugAndroidTest

# 配置签名后执行正式构建
.\android\gradlew.bat -p android :app:assembleRelease

# 分发渠道需要 AAB 时
.\android\gradlew.bat -p android :app:bundleRelease
```

编辑器资源构建与 `versionName` 生成须加入 Gradle 依赖链；不能依靠开发者手动复制 assets 才能构建。修改 WebView 编辑页面时另做其适用的资源 / 语法与实机验证。

CI 在现有 [verify workflow](../../.github/workflows/verify.yml) 基础上增加 Android 作业，缓存与工具链独立，保护签名材料。契约向量变更运行 TypeScript 和 Kotlin 两侧测试；模拟器任务与真机记录分别报告。

正式发布完整执行 [AGENTS.md](../../AGENTS.md) 的版本、CHANGELOG、验证、提交、标签、推送、部署和 Release 流程；预发布采用新预发布标签，不替换稳定版 Latest。Android 的额外构建不能代替现有 Web / 后端检查。
