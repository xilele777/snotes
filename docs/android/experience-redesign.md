# Android 体验改造：与 Web 手机端保持一致

日期：2026-11-20。范围：现有 Kotlin / Compose 客户端的本地实现与验收，不是正式发布。应用版本继续读取根 `package.json`。

## 跨端一致性基准

2026-11-20 根据用户偏好修正设计方向：Android 的页面逻辑和布局与 Web 手机端保持大体一致，部分内容结合 Android 特性优化。以下规则作为实现与验收基准；本轮实现与上一轮独立界面改造分别记录。

| 区域 | Web 手机端基准 | Android 对齐目标与适配 |
| --- | --- | --- |
| 导航 | 手机抽屉；笔记区包含随手记、全部笔记、星标笔记、已隐藏；整理区包含笔记本和分组；底部工具包含回收站、统计、设置 | 保持入口组织、名称与含义；使用原生抽屉处理遮罩、焦点和系统返回；宽窗口按可用空间呈现导航 |
| 笔记列表 | 顶栏为抽屉入口、当前视图标题 / 数量、新建；下方是搜索、排序和刷新，再展示笔记 | 搜索直接作用于当前列表范围；新建沿用当前分组或笔记本语境；减少额外宣传标题，保持标题、摘要、日期和状态的层级 |
| 筛选逻辑 | 随手记仅展示独立且未隐藏内容；全部笔记、星标和分组覆盖符合条件的笔记本内容；已隐藏只影响随手记曝光 | 沿用同一业务规则，区分随手记与全部笔记；正文未下载时明确说明搜索覆盖范围 |
| 编辑详情 | 手机列表进入单篇详情，返回原列表；保留标题、编辑 / 阅读、保存状态和对象菜单 | 保持主要操作的位置关系与流程；键盘上方格式工具可以原生适配，退出继续等待保存 flush；未验收的富文本模式明确标为试用 |
| 笔记本 | 总览 → 目录 → 笔记；搜索 / 排序 / 新建位于总览；目录节点操作归属相应节点菜单 | 保持浏览层级、创建位置和菜单语义；弹窗与文件操作按 Android 交互实现 |
| 设置 | 外观、数据、快捷键、Agent 接入、关于；返回原工作区 | 已支持设置按相同类别组织；服务器连接与本机空间作为 Android 特有内容补充；未支持类别记录差异 |
| 视觉 | 以 `src/styles.css`、`src/ui-tokens.css` 和实际手机布局为基准 | 延续蓝色重点色、浅 / 深色表面、图标语义和文字层级；尺寸按 dp / sp、至少 48 dp 触控目标及系统字体缩放调整 |

核对来源：[Web 工作区](../../src/App.vue)、[抽屉导航](../../src/components/GroupSidebar.vue)、[笔记列表](../../src/components/NoteList.vue)、[页面返回与状态](../../src/navigation.ts)、[设置分类](../../src/components/SettingsPage.vue)。一致性以用户可见行为为准，原生层继续负责数据库、同步和系统能力。

允许的平台优化包括键盘 / IME、安全区和系统栏、系统返回与预测性返回、分享与接收分享、Photo Picker / SAF、本机保存与 WorkManager 后台同步，以及平板和折叠屏的窗口适配。页面内容关系、筛选规则和操作结果继续沿用 Web 基准。

### 本轮实现

- `WorkspaceNavigation` 替换四栏底部导航；手机抽屉与宽窗口常驻侧栏使用相同入口组织，回收站、统计、设置作为独立工具入口。同步面板可从当前页面打开，抽屉关闭时清理焦点与键盘。
- `NotesScreen` 使用列表顶栏新建、列表内搜索 / 排序 / 刷新和紧凑内容行，移除宣传标题与 FAB。标题显示当前视图与结果数量；正文缺失提示按当前视图统计。
- Room 查询区分随手记、全部笔记、星标、分组、已隐藏；随手记排除使用中笔记本的引用与隐藏内容，单篇显示覆盖分组默认。菜单支持隐藏、显示及恢复跟随分组；最近更新 / 最近创建 / 标题排序均保留置顶优先。
- `NotesViewModel` 使用 `SavedStateHandle` 保留各视图的搜索和排序；列表滚动与笔记本选择沿用 `SaveableStateHolder`。从详情、设置、统计与回收站返回保留原工作区上下文。
- 原生主题和本地编辑页面映射 Web 的浅 / 深色蓝色语义配色、文字层级与较小圆角；WebView 继续使用底部格式工具与原生键盘 / 安全区适配，保存流程沿用原有 flush 与草稿恢复。
- 设置分为外观、数据、关于；连接、本机空间、备份和恢复放在数据页。统计独立展示本机笔记、笔记本、打开次数和回收站数量。
- 笔记本总览增加搜索、名称 / 更新时间排序与使用中 / 已归档筛选，新建入口移到顶栏；目录节点可折叠。根目录或章节内的新建明确指定位置，并在同一事务内保存笔记、目录与任务；章节菜单支持新建、加入笔记与子章节。

### 剩余能力差异

本轮完成主要页面结构和既有功能流程的对齐，尚未实现 Web 全部能力。Android 设置暂不提供 Web 的快捷键与 Agent 凭证管理；统计暂不包含 Web 的字数、写作趋势与热力图；列表暂不包含多选批量操作、正文命中高亮与多关键词匹配；笔记本暂不包含固定偏好与完整创建位置选择器。编辑器即时渲染继续处于试用阶段，完整富文本模式沿用原有输入法验收门禁。

验收以相同内容、相近手机窗口、浅 / 深色主题核对两端截图，并走同一组新建、搜索、星标、分组、笔记本、回收站和返回流程；自动化通过与跨端布局完成分别记录。

## 上一轮问题诊断

原界面具备离线保存、同步、恢复等能力，但主要按“功能如何验收”组织界面，而不是按“用户如何记录”组织。代码审查及当前模拟器截图确认以下问题：

| 区域 | 原有问题 | 对体验的影响 | 本次处理 |
| --- | --- | --- | --- |
| 首页 | 版本、连接、同步、搜索说明、回收站、恢复与原型入口同时出现 | 首屏信息密度高，笔记内容不突出 | 简洁标题、同步摘要、筛选 chips、内容卡片；连接收入底部面板 |
| 导航 | 五个入口用字符代替图标，回收站与日常写作同级 | 视觉不一致，低频功能占据拇指区域 | 四个常用入口，统一矢量图标；回收站归入设置 |
| 笔记卡片 | 标题、摘要和“操作”文字缺少层级，置顶不明显 | 难以扫读、无法判断组织关系 | 标题、摘要、日期、分组分层；星标和置顶独立标识；菜单图标 |
| 编辑器 | 原生阅读入口与 Web 模式入口重复；格式工具挤在正文上方；正文套输入框边框 | 页面像表单，写作空间被多行按钮侵占 | 顶栏保留返回、保存状态、插图与菜单；模式入口统一，格式工具移到底部 |
| 笔记本 | 列表、目录、结构操作、危险操作混排；每个节点展开多个按钮 | 目录难读，操作密集，误触风险高 | 卡片列表进入独立目录页；节点菜单与笔记本菜单按对象组织 |
| 设置 | 偏好和运维说明以连续文本排列，主题用圆点表示选择 | 缺少分区，难以发现可操作项 | 按连接、外观、恢复、备份和空间分区，主题 chips 与字号预览 |
| 空白 / 异常 | 多数状态只有一行文字；错误提醒和正常状态混排 | 新用户不知道下一步，失败难发现 | 按搜索无结果、星标、分组、回收站、笔记本分别引导；保留恢复和重试 |
| 窗口与键盘 | 列表不随窗口调整，部分 padding 未消费 | 宽屏拉伸、键盘占位和系统安全区容易不一致 | 自适应导航与笔记网格、内容宽度上限、统一 safeDrawing 与消费逻辑 |

改造前截图：[首页](../../artifacts/android/ux/before-home.png)、[编辑器](../../artifacts/android/ux/before-editor.png)。截图与 APK 属于本地验收产物，保存在已忽略的 `artifacts/android/`。

## 上一轮设计规则

目标是让用户更快找到内容、开始写作、理解保存状态。使用暖白纸面与墨绿重点色，深色使用对应的语义配色。既有数据、安全边界和同步协议继续由原来的 Repository / ViewModel 承担。

- 页面背景、卡片、分隔线、重点、次要文字、错误分别使用 Material 3 语义色，禁止页面独立拼凑主题颜色。
- 页面留白 20 dp；卡片内部 16–20 dp；同组操作间距 8 dp；卡片间距 12–16 dp。
- 标题 17 sp、摘要 14 sp、元信息 12 sp，行高独立设置；列表标题最多两行，详情保留完整内容。
- 原生图标操作使用 Material `IconButton`，具有至少 48 dp 的触控区域和可访问名称。Web 工具至少 44×48 CSS px。
- 常用入口稳定可见；分组、格式、分享、历史等低频操作按所属对象收入菜单。破坏性操作继续确认，删除笔记继续支持撤销。
- 主操作每页最多一个明显的 FAB：新建笔记或新建笔记本。
- “已保存到本机”与同步状态分别表达，不用“已同步”描述仅本地持久化的内容。正文缺失仍展示不可用与重试，不能伪装成空笔记。
- 尊重系统字体缩放；列表采用稳定 ID；保存与退出仍走现有 flush / 草稿恢复流程。

## 上一轮已实现

1. `core/ui/SnotesTheme.kt`：浅色 / 深色完整语义配色、字号、行高与圆角。`Components.kt`：矢量图标、空状态、设置行和分区标题。
2. `MainActivity`：使用 Material 3 `NavigationSuiteScaffold`，紧凑窗口使用底部导航，宽窗口根据官方窗口分类使用侧栏；四个常用入口。自定义浅色 / 深色偏好同步更新系统栏图标。
3. `NotesScreen`：自适应 Paging 网格、简洁首页、搜索与清除、chips 筛选、置顶与星标标识、日期和分组、同步面板、连接表单、异常提示与删除撤销。新建按钮保留在笔记页，搜索页专注检索；切换导航时清理输入焦点与软键盘。
4. `LocalEditorScreen` 与 `editor-web`：保留一个模式入口；格式工具在正文下方，跟随原生键盘调整后的 WebView；阅读模式隐藏格式工具；正文聚焦使用细侧线，强制颜色模式回退到系统 outline；常规保存成功沿用顶栏显示，Web 状态区保留无障碍播报，警告和保存失败继续可见。保留选区、撤销、组合输入保护、源码与预览的原始 Markdown 保真。
5. `BooksManagerScreen`：卡片列表、独立目录浏览、章节与引用笔记按钮、节点菜单、笔记本菜单、目录历史和删除确认。名称、简介、选择状态在 Activity 重建后保留。
6. `SettingsScreen` / `DataTools`：分区卡片、主题选择与字号预览、内容恢复、备份和数据空间，原型与版本移到页面末尾。
7. 统一边距：页面 `Scaffold` 处理安全区；滚动列表把 padding 传入 `contentPadding` 并消费；编辑器使用 `WindowInsets.safeDrawing`，避免额外 IME padding 重复占位。
8. `WorkspacePreviews`：手机、折叠屏、平板、桌面各一组浅色 / 深色组件预览。`WorkspaceExperienceTest` 运行真实导航 / 重建流程并生成页面截图。现有离线编辑、分组、搜索、星标、回收站与原型测试更新到新的入口。

## 上一轮 Skills 与技术取舍

使用 `adaptive` 指导窗口分类、导航和网格、状态恢复；使用 `edge-to-edge` 统一系统栏与键盘边界；使用 `android-cli` 获取官方文档、设备信息和截图；使用 `modern-web-guidance` 的 `form-factor-adaptation` 检查 Web 工具触控目标、容器响应、语义名称和窄屏换行，使用 `accessibility` 保留焦点指示、强制颜色回退和状态播报。

本轮采用现有导航状态配合官方 NavigationSuiteScaffold。完整 Navigation 3 和平板列表 / 编辑双窗属于下一轮结构迁移，需要同时迁移编辑会话、分享入口与 ViewModel 生命周期。当前没有增加实验性 Grid / FlexBox 或把双窗布局手工拼进保存流程。笔记网格使用已有 Compose 的稳定 LazyVerticalGrid。

## 验收与后续

本轮自动化与模拟器验收结果见 [Web 对齐验收](acceptance/2026-11-20-web-alignment.md)，上一轮独立设计结果保留在 [历史验收](acceptance/2026-11-20-ui-redesign.md)。建议按以下顺序验收：

1. 手机：首页 → 新建 → 输入 Markdown → 返回 → 搜索 → 星标 → 删除与撤销 / 恢复。
2. 编辑器：键盘展开与收起、中文组合输入、格式选区、预览往返、最后一次输入后立即退出、旋转与恢复。
3. 笔记本：新建、添加章节、引用与打开笔记、节点移动、归档、目录历史。
4. 设置：主题与系统栏对比、字号最大值、连接失败的内联提示、恢复入口和备份操作。
5. 宽窗口与横屏：常驻侧栏、导航切换、查询保留、安全边距、编辑区域可用高度。

导航、列表、视觉和设置的主要对齐已完成本地实现与模拟器验收；剩余能力差异见上文。后续改造按收益和风险排序：

| 优先级 | 下一轮内容 | 完成标准 |
| --- | --- | --- |
| P1 | Navigation 3 与大屏列表 / 编辑双窗 | 分享与进程恢复正确、编辑会话无串写，旋转 / 折叠保留选中内容 |
| P1 | 真机输入法和无障碍验收 | 常用中文 IME 连续输入无丢字，TalkBack 与大字号覆盖关键流程 |
| P2 | 列表多选与批量分组、移动、回收 | 明确选择状态与撤销边界；保留引用笔记结构约束 |
| P2 | Markdown 编辑体验增强 | 常用格式一键操作、长文目录与查找，在原始文本保真测试后开放 |

正式发布仍按根 `AGENTS.md` 同步应用版本、更新 CHANGELOG、验证、提交和标签、部署及 GitHub Release。本轮不创建发布标签。
