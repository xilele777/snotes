日期：2026-11-19（Asia/Shanghai）。结果：M1 原型实现、浏览器测试与现有模拟器自动化通过；人工拼音候选、TalkBack 和真机性能未验收。采用源码 + 预览推进后续本地笔记，短文即时渲染保留试用状态。

## 交付范围

- 启动页增加“打开离线编辑器原型”，可编辑样例 A、样例 B 和 82,903 字符 / 2,000 段落长文。
- 默认 textarea 源码编辑，按需本地 Lute 预览，短文可进入 Vditor IR。初始化、预览和未编辑的模式转换不写回原稿；长文不创建 IR DOM。
- origin 与主 frame 限定的消息桥，校验 profile / note / session / revision / request，隔离旧消息与撤销历史。
- 原生串行保存、同会话输入合并、800 ms debounce、原子草稿和提交 receipt；导航等待实时 flush 与持久化 ACK，失败保留正文并提供重试 / 分享。
- Activity 重建前完成已捕获输入的保存；重启恢复未提交草稿，已提交的旧草稿不重放，基线冲突保留两份正文。
- 页面与资源从独立 lockfile 打包，原生拦截非本地请求；没有正文 localStorage、IndexedDB、Service Worker 或公网 CDN。旧 WebView 的预览净化使用打包的 DOMPurify。

源码主要位于 `android/editor-web/`、`android/app/src/main/java/io/github/xilele777/snotes/core/editor/` 和 `feature/editor/`。当前保存仓库是应用私有 `files/editor-prototype/` 中的测试 JSON / 草稿文件；没有接入 Room、真实笔记列表、服务端、令牌或同步。

工作区仍未提交，应用版本仍来自根 package.json；没有修改根版本、打标签、推送或部署。原有 Web 交互与安全响应头改动保留。

### 本轮发现并修正

- Vditor 4.0.0 在 WebView 禁用 DOM 存储时仍读取 null localStorage；打包时对固定版本的 capability check 增加单点 null 判断，匹配变化即拒绝构建。
- Vditor destroy 移除资源 script ID；重建时恢复已经加载的标记，避免同步 XHR 与 CSP 冲突。
- 首次视觉检查发现 WebView 把源码区测量为一行；显式 MATCH_PARENT 与本地页面百分比高度修复，新增实际 viewport / 源码高度断言。
- 输入测试最初在错误线程操作 Chromium InputConnection，整轮运行出现中间文本重复与断言失败；改按连接提供的 handler 执行 batch edit，最终完整 8 项测试通过。

## 待验收边界

人工拼音候选、选区 / 撤销习惯、TalkBack、横屏 / 小屏 / 放大字体、常用第三方输入法和厂商设备行为仍待验收。没有形成真机冷启动、输入延迟或长文预览 P95 数据。

保存确认仅覆盖已经持久化的 revision。正在输入但尚未写入的窗口仍可能在立即杀进程时丢失，不能从正常返回或 Activity 重建推导“最后一个字绝不丢”。原型冲突副本保留在测试仓库中，完整恢复管理界面在 M2 接入。

下一步 M2 将此保存会话接入 Room、笔记列表、本地正文、事务 outbox 与草稿恢复管理；同步在 M3 实现。
