## 实现范围

- 默认进入本机笔记首页，提供新建、源码编辑 / 预览、星标、创建分组 / 移动笔记、搜索、回收站、删除撤销与恢复。编辑器复用 M1 的消息协议、WebView 和串行 SaveSession；原型样例入口仅在 Debug 首页显示。
- Room 2.8.5、Paging 3.5.3 固定在版本目录。版本依据为 [Google Room Maven 元数据](https://dl.google.com/dl/android/maven2/androidx/room/room-runtime/maven-metadata.xml)与 [Paging 元数据](https://dl.google.com/dl/android/maven2/androidx/paging/paging-runtime/maven-metadata.xml)。没有调整 M0 工具链或根应用版本。
- 活跃 profile 为 `local-default`，数据库、WAL、草稿与图片目录位于应用私有 `files/profiles/local-default/`；没有把 M1 的 `files/editor-prototype/` 样例作为真实笔记迁移。profile ID 校验与会话校验防止跨实例写入。
- Room schema 1 导出到 `android/app/schemas/io.github.xilele777.snotes.core.database.NotesDatabase/1.json`，包含 notes、bodies、groups、outbox、sync_meta、history、drafts、editor_receipts、knowledge_bases、tocs、note_states、images。元数据与正文分表，外键保护正文 / 历史；不启用 destructive migration。
- 正文、派生标题 / 摘要 / 缩略图、历史、body 任务和会话 receipt 在同一事务内提交。新建与 create 任务同事务。属性任务累积已修改字段；trash / recover 清除对方任务并保留最终意图；实体类型隔离笔记和分组任务。
- 本地编辑不自行增加服务端 version / body_version / prop_version。界面分别显示“已保存到本机”和“尚未同步”，待同步数量来自持久化 outbox；M3 才接入真实服务端。
- 历史参考共享规则：5 分钟间隔或可见字符变化达到 100 时记录被替换的旧正文，每篇保留最近 20 条、最多 30 天；空正文不生成普通历史快照。基线冲突另外保留完整库中正文为可见冲突副本。
- 列表使用 Paging，每页 30 条，仅返回元数据；详情按 ID 读取正文，缺失行与空串区分。中文搜索使用绑定参数的 `instr` 子串查询，200 ms debounce / flatMapLatest 取消旧分页；标题、摘要和本机正文参与搜索，界面提示未下载正文数量。
- 原子草稿文件先落盘，Room drafts 是额外镜像；镜像写入失败仍保留文件恢复通道。正文事务失败不发保存 ACK。恢复同时读取文件与 Room，按会话 revision 去重，已提交日志只清理，未提交日志检查基线后保存；损坏文件保留并显示恢复入口。
- 恢复入口支持重试、草稿另存与正文分享；另存操作与 receipt / 副本映射同事务，重复操作复用同一副本，旧 revision 不降低已提交 receipt。已删除笔记的草稿另存为新笔记，不能自动复活原笔记。
- 单篇 Markdown 通过系统 CreateDocument 导出，UTF-8 写入原文，不申请广泛存储权限。导出快照在 ViewModel 中跨 Activity 重建保留；进程死亡导致快照丢失时提示重新导出。原有备份与设备迁移排除规则继续覆盖私有数据。

源码主要位于 `core/database/`、`core/data/NotesRepository.kt`、`core/editor/DraftJournal.kt`、`feature/notes/` 与 `feature/editor/LocalEditor*`。原有 Web / 后端改动保留，未暂存、提交、推送、部署或打标签。

### 本轮发现并修正

- 原有 SaveSession 先关闭通道再取消 actor，在真实 IO 线程上可能抛出 ClosedReceiveChannelException；改为先取消接收者，注入保存失败的 Room 测试验证关闭路径。
- Hilt instrumentation 入口放在 androidTest 中不能加入普通应用的组件；移动到 debug 源码集，Release 不包含该测试入口。
- 模拟器 System UI 无响应对话框抢占了窗口，导致原生输入注入失败。确认窗口和 UI dump 后关闭该系统对话框；输入测试增加目标窗口 / IME 状态等待，随后单项和整轮通过。
- 草稿另存增加持久化副本映射与 receipt 最大值保护，防止重复另存或处理旧 revision 时倒退提交记录。

### 复现

```powershell
.\android\gradlew.bat -p android :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:connectedDebugAndroidTest --no-daemon --console plain
.\android\gradlew.bat -p android :app:assembleRelease :app:lintRelease --no-daemon --console plain

# Gradle 的 connected 任务结束后会卸载测试包；跨进程验证前重新安装两份 Debug APK。
adb -s emulator-5580 install -r android/app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5580 install -r -t android/app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
.\android\scripts\verify-process-recovery.ps1 -AdbPath '实际 SDK 路径\platform-tools\adb.exe'
```

ProcessRecoveryFixture 由跨进程脚本驱动，默认不随普通 connected 任务执行；其 prepare / verify 不能当作同一进程内的独立测试随意排序。如果 prepare 完成后进程已经退出，脚本明确提示只覆盖新进程恢复，不能据此宣称立即强杀通过。脚本使用指定模拟器，不停止全局 ADB 或其他设备。

本地正文保存限制为 1 MiB UTF-8，超限输入保留草稿并可分享 / 拆分；没有截断原文。冲突副本添加标题前缀后可能超过此限制，仍完整保留本地内容，M3 发送前必须阻止超限任务并给出处理入口。

当前没有连接令牌、远端同步、图片下载、笔记本网络读取或数据库旧版本升级。schema 1 是首次真实 Room 数据库，尚无旧 Room schema 可做迁移升级验收；未来增加版本必须提供显式迁移和旧库测试。

SQL trigger 验证的是事务写入失败路径，没有模拟真实设备磁盘耗尽。大量中文正文搜索、取消时延与真机性能预算留待产品样本 / M6 测量。模拟器 InputConnection 与 DOM 自动化不代表人工拼音候选、TalkBack 或第三方输入法已经验收。
