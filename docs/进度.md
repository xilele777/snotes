## 开发中发现的坑

- **快捷键里的数字键要看 `event.code`**。Ctrl+Shift+1 在多数键盘上 `event.key` 是 `!`，不能按 `key` 判断数字；`resolveShortcut` 优先读 `code` 的 `DigitN`，没有 `code` 时再退回 `key`。不带 Shift 的 Mod+数字是浏览器切标签，不能抢。
- **上下条切换不能用单独的 Alt+方向键**。Mac 编辑器里 Alt+方向键是按词移动光标，改成 Mod+Alt+方向键。
- **快捷键触发的属性变更是异步落库的**。App 级单测里按键后要用 `vi.waitFor` 等 `setProps` 走完 IndexedDB，`flushPromises` 一次不够。
- **一次性用 heredoc 往多个文件写含 `\n` 的 Python 字符串容易把转义吃掉**，落盘后变成真实换行导致 TS 语法错误。逐文件用 Write 或 Edit 工具更稳。
- 沿用上次：新建笔记后的输入窗口（E2E 用 `createNoteAndWait`）、长按测试要显式开 `hasTouch`。
- **未跟踪文件**：`pelican-cycling.html`、`shot.tmp.mjs`、`docs/对话交接.md` 不是本项工作的产物，没有纳入任何提交。
