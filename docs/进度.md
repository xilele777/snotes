## 关键实现位置

- 限流本体：`server/rate-limit.ts`。`LoginLimiter` 按 key 计数，`fail()` 返回本次触发的封锁毫秒数，`blockedFor()` 查剩余封锁，`succeed()` 清零；记录条数上限 10000，按 Map 插入序淘汰最久没动的。`clientAddress(remote, forwardedFor)` 只在 socket 对端是回环或私网地址（`isTrustedProxy`）时才采信 `X-Forwarded-For`，从右往左取第一个非内网地址；整条链路都是内网时取最左侧。
- 接入点：`server/app.ts` 在 `bodyLimit` 之前给 `/api/*` 挂中间件，`/api/health` 跳过；响应 401 就 `fail`，其它状态 `succeed`。`createServerApp(assetDirectory, limiter?)` 第二个参数便于测试注入。
- 来源地址：`server/index.ts` 的 `serve()` 回调把 `bindings.incoming.socket.remoteAddress` 放进 `Env.REMOTE_ADDRESS`（`worker/types.ts` 新增可选字段，Worker 不设置）。
- 前端：`src/api/client.ts` 的 `request()` 对 429 先读 body，只有 `error === 'too_many_attempts'` 才 `clearToken()` 并调用 `src/api/token.ts` 新增的 `markTooManyAttempts(retryAfter)`，提示「尝试次数过多，请 N 分钟/秒后再输入访问令牌」；其它 429（如 Cloudflare 速率限制）不动令牌，照旧按可重试错误抛出。`TokenGate.vue` 无需改动，复用 `authNotice`。
- 打印：`src/styles.css` 末尾的 `@media print` 块。
- 文档：README「安全说明」加两条（服务器版限流规则、Cloudflare WAF 配置建议）；`docs/server-deployment.md` 新增「登录限流与反向代理」小节，说明可信代理判定与 Nginx 需转发 `X-Forwarded-For`。

## 开发中发现的坑

- **`app.request()` 的第三个参数就是 `Env`**，测试里给每个请求传不同的 `REMOTE_ADDRESS` 即可模拟不同来源，不需要真的起 HTTP 服务。
- **限流用例要打一个鉴权后能返回 200 的端点**。`GET /api/groups` 不存在（分组只有 POST/PATCH/DELETE），会得到 404 而不是 200；用 `POST /api/sync/pull` 并带 `{ since: 0 }` 请求体，否则是 400 `invalid_since`。
- **遗忘期要从封锁结束算起**。若只看上次失败时间，被封 1 小时的来源在封锁期满时早已超过 15 分钟遗忘期，一解封就回到初始状态，翻倍封锁形同虚设。
- **Node 的 IPv4 映射地址**形如 `::ffff:127.0.0.1`，可信代理判定前先归一化。
- **Playwright 起 wrangler 的 webServer 偶发 120 秒超时**，日志里没有报错，重跑即可；与上次的 vitest runner 偶发同属环境抖动。
- **vite dev 直接看页面**：`vite.config.ts` 把 `/api` 代理到 8787，没起 `wrangler dev` 时列表为空但界面可用，够核对纯样式改动。
- 沿用上次：跑 E2E 前 `unset HTTP_PROXY HTTPS_PROXY`；E2E 全量约 4.5 分钟，终端长时间无输出属正常。
