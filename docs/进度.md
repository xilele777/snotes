## 开发中发现的坑

- **新建笔记后的输入窗口**。`src/stores/notes.ts` 的 `create()` 要 `await repo.createNote()` 再 `await load()` 才设置 `currentId`，这中间编辑器仍挂着上一条笔记的正文。本地实测窗口约 60ms，人手点完「新建」立刻打字基本碰不到，但测试是零延迟打字的，会把字符写进旧笔记的节点再被 `replaceContent` 冲掉。E2E 已加 `createNoteAndWait()` 等待编辑器真的换页。要彻底消除这个窗口，思路是在 `create()` 里更早设置 `currentId`，或在切换期间让编辑器暂时不接受输入。
- **长按类测试要显式开 `hasTouch`**。Playwright 默认上下文是桌面形态，不派发触摸事件，`page.touchscreen` 不可用。`tests/e2e/full-flow.spec.ts` 里用 `test.describe` + `test.use({ hasTouch: true })` 单独开了一个块，再用 CDP 的 `Input.dispatchTouchEvent` 模拟按住不放。
- **未跟踪文件**：`pelican-cycling.html`、`shot.tmp.mjs`、`docs/对话交接.md` 不是本项工作的产物，没有纳入任何提交。
